# Miku Repository Review — 2026-07

A full audit of the `miku` IM server (C99-C23, CMake). Findings are grouped by
severity with exact file:line references. The remediation plan prioritises
correctness first (the test harness was silently swallowing failures), then
memory safety, then performance, then CI hardening.

## Executive Summary

The project builds cleanly (`-Wall -Wextra -Wpedantic -Wconversion`, 0 warnings)
and ships 13 binaries. However the test framework had a defect that caused
**every test suite run to exit 0 regardless of failures**, which masked three
real functional bugs and let memory-safety regressions ship undetected. ASAN
surfaced a dangling-pointer API bug, undefined behaviour in the protobuf
encoder, and unchecked allocations in the HTTP server.

After remediation all 195 tests pass under both Debug and ASAN builds.

## Critical Findings

### C1. Test harness reports success on failure (silent green CI)
- `tests/miku_test.h:105` `mk_run_test` unconditionally runs `mk_tests_passed++`
  and prints `OK`. The `if (... || 1)` block is dead code.
- `mk_tests_failed` is never incremented, so `mk_test_summary` always returns 0.
- Effect: CI's `timeout 60 ./build/bin/miku_tests` step is always green.
  Three actually-failing tests were hidden:
  - `test_msg_pull_by_seq_range` (`tests/test_new_modules.c:1272`)
  - `test_group_member_sync_callback` (`tests/test_new_modules.c:2562`)
  - `test_admin_stats` (`tests/test_new_modules.c:3156`)

### C2. `miku_error_msg` returns a dangling pointer
- `src/foundation/miku_error.c:31` takes `miku_error_t` **by value** and returns
  `err.msg`, which points into the by-value copy's now-dead stack frame.
- ASAN: `stack-use-after-return` in `test_error` (`tests/test_foundation.c:119`).
- The struct is 260 bytes (`int` + `char[256]`), so pass-by-value is also
  needlessly expensive.

### C3. Undefined behaviour in protobuf svarint encoder
- `src/protocol/miku_pb.c:71` `(val << 1)` where `val` is `int64_t` and may be
  negative — left-shifting a negative signed value is UB in C.
- ASAN/UBSan: `left shift of negative value -1`.

### C4. Unchecked allocations in HTTP server
- `src/protocol/miku_http_server.c:86-87` `realloc` results are assigned
  directly to `srv->conn_fds` / `srv->conn_last_active`; on failure the original
  pointer is leaked, `conn_cap` is bumped anyway, and the next access
  dereferences NULL. Also a `realloc`-on-failure leak.
- `src/protocol/miku_http_server.c:405-406` `malloc` results unchecked.

### C5. `sendBusinessNotification` double-gate defeats admin bypass
- `src/services/msg/miku_msg.c:632` computes its own `gate` then calls
  `miku_msg_send`, which re-runs `msg_send_gate` (`miku_msg.c:196`). The admin
  bypass (`gate = 0`) is therefore discarded and admin direct notifications hit
  `6002 not mutual friends`.
- `send` (`miku_msg.c:602`) and `sendSimpleMsg` (`miku_msg.c:619`) have the same
  double-gate pattern — a redundant O(1) but unnecessary cost on the send hot
  path, and a latent correctness trap.
- API layer (`src/gateway/api/miku_api.c:1211`) rejects all non-admin
  `sendBusinessNotification` with 403, but group-targeted notifications are
  expected to be gated by group membership (3003) instead.

## High Findings

### H1. `pullMsgBySeq` omits `data` on the validation-error path
- `src/services/msg/miku_msg.c:688` `break`s before setting `data`, so the
  response has no `data` field. Callers expecting a (possibly empty) `data`
  array get NULL.

### H2. Test helper `make_req` stack-use-after-return
- `tests/test_protocol.c:766` parses into a local `char buf[4096]`; the parsed
  request's `path.data` aliases `buf`, which dies on return. ASAN flags
  `path_equals` (`src/protocol/miku_middleware.c:68`). Same issue in
  `make_req_with_token` (`tests/test_protocol.c:779`).

### H3. Memory leaks surfaced by ASAN
- LeakSanitizer reports a ~168 MB single allocation plus ~28 MB across millions
  of small objects during a full test run. Most originate in test fixtures that
  allocate JSON/services without teardown. Not addressed in this pass (tracked
  below); the correctness fixes above take precedence.

## Medium Findings

### M1. CI has no ASAN/UBSan job and no caching
- `.github/workflows/ci.yml` runs only a Debug build + test. No sanitizer job,
  no `ccache`, no release build verification. C2/C3 above would have been caught
  by a sanitizer job.

### M2. CI test step cannot detect failure
- Even with C1 fixed at the harness level, the CI `Test` step relies on the
  process exit code. This is now correct once C1 is fixed, but worth noting.

### M3. `march=native` in the default Release flags
- `CMakeLists.txt:61` uses `-march=native`, which produces non-portable binaries
  (e.g. AVX-only instructions). Fine for local builds; risky for distributed
  release artifacts. Left as-is (no release artifact pipeline exists yet).

## Low Findings

### L1. README stat drift
- README claims 171 tests / ~15K LOC; actual is 195 `mk_run_test` calls and
  18,254 LOC (15,534 `.c` + headers). Cosmetic.

### L2. No `.dockerignore`
- `Dockerfile` `COPY . .` ships `build/`, `build-asan/`, `.git/`, `notes.html`
  (70 KB), `ARCHITECTURE.md` (62 KB) into the build context, inflating context
  and layer cache churn.

## Remediation Plan (performance-optimal ordering)

The ordering below front-loads the change that unblocks all other verification,
then memory safety, then the perf-aligned correctness fixes.

1. **Test harness** (`tests/miku_test.h`): track failures via a per-test flag
   set before each assertion's `return`; `mk_run_test` inspects it to bump
   `mk_tests_failed` instead of unconditionally bumping `mk_tests_passed`.
   `mk_test_summary` exit code now reflects reality.
2. **`miku_error_msg`** (`miku_error.h`, `miku_error.c`): take
   `const miku_error_t *` and return `err->msg`. Update the single caller.
   Removes the dangling pointer and the 260-byte by-value copy.
3. **`miku_pb.c` svarint**: cast to `uint64_t` before the left shift.
4. **HTTP server allocs** (`miku_http_server.c`): check `malloc`/`realloc`
   returns; on `realloc` failure preserve the old pointer and abort the grow.
5. **`pullMsgBySeq`** (`miku_msg.c`): always attach a `data` array (empty on
   the validation-error path).
6. **`sendBusinessNotification`** (`miku_msg.c`, `miku_api.c`): extract
   `msg_store_internal` (store without gate) so `miku_msg_send` gates once and
   the RPC handlers stop double-gating. New gate logic:
   group-targeted → `msg_send_gate` (3003 on non-member, applies to all);
   admin direct → presence check only (bypass friend check);
   non-admin direct → 403 (API layer). API layer relaxes the admin requirement
   only when `groupID` is present.
7. **Test helpers** (`tests/test_protocol.c`): make the parse buffer `static` so
   `path.data` stays valid for the request's lifetime (sequential test use).
8. **CI** (`.github/workflows/ci.yml`): add an `asan` job running the ASAN/UBSan
   build, and make the test step explicitly fail on non-zero exit.
9. **Docs**: refresh README stats; this review doc is the changelog of record.

## Verification

- `cmake --build build -j$(nproc)` — 0 warnings, 0 errors.
- `./build/bin/miku_tests` — 195/195 pass, exit 0.
- `./build-asan/bin/miku_tests` — 195/195 pass, no ASAN/UBSan errors (leaks
  deferred per H3).
